# ТЗ на ML-часть

Кому: тому, кто обучает модели. Что нужно: десять артефактов, которые сервис уже умеет
загружать. Код инференса написан и покрыт тестами; здесь — что именно положить в бакет и
как понять, что оно годится.

Формат артефактов и команды публикации — [docs/ml.md](ml.md). Здесь — требования к данным,
обучению и приёмке.

## 1. Рамки

Входит: голова классификации сетки (5 штук), YOLO-детекторы (4 штуки), регрессор поворота (1).

Не входит и обучать не надо:

| тип | почему |
|---|---|
| `text_captcha` | LLM по HTTP (`LLM_ENDPOINT`), это конфиг, не веса |
| `image_to_text`, `math_image` | PaddleOCR / TrOCR из коробки |
| `audio_captcha`, reCAPTCHA v2 audio | Whisper из коробки |
| `slider` | классическое сопоставление краёв, модель не нужна |

## 2. Контракт инференса

Сервис грузит артефакт по имени и не знает, как ты его учил. Что фиксировано:

- **Голова классификации**: `safetensors` с `classifier.weight [C,768]` и `classifier.bias [C]`.
  Backbone — `google/vit-base-patch16-224-in21k`, заморожен, 768-мерный пул на тайл.
  `meta.json.labels` — словарь `{"bus": 0, ...}`, порядок = порядок строк матрицы.
- **Детектор**: обычный `.pt` ultralytics. `model.names` — имена классов так, как они
  приходят в промптах (`bus`, `crosswalk`, `traffic light`).
- **Поворот**: `resnet50` state_dict, последний слой `fc` → 2 (`sin θ`, `cos θ`).

Бюджет латентности на CPU (без батчинга, один запрос):

| модель | бюджет p95 |
|---|---|
| голова на 9 тайлов | ≤ 30 мс |
| YOLO-детектор | ≤ 40 мс |
| регрессор поворота | ≤ 15 мс |

Если не влезает — уменьшай вход (ViT-B/16 → patch16-224 уже минимум; YOLO n/s вместо m).

## 3. Артефакты

### 3.1 `rotate-v1` — регрессор угла

- **Вход**: RGB-кроп капчи, повёрнутый на неизвестный угол. **Выход**: угол 0..360.
- **Данные**: синтетика, разметка не нужна. 100 000 изображений: любые капчи + ImageNet-кропы,
  каждый повёрнут на случайный угол из U(0,360). Валидация 5 000, отдельно — 1 000 реальных
  капч с известным углом (снятых вручную).
- **Обучение**: `resnet50(weights=IMAGENET1K_V2)`, `fc` → `Linear(2048, 2)`, лосс — косинусный
  между предсказанием и `(sin θ, cos θ)`. Аугментации: только поворот, яркость, JPEG-шум —
  никаких флипов и кропов, они ломают угол.
- **Приёмка**: MAE ≤ 3°, доля ошибок ≤ 5° — ≥ 95% на валидации и ≥ 90% на реальных.
- **Закрывает типы**: `rotate`, `captchafox` (rotate-вариант), FunCaptcha rotate.

### 3.2 `click-v1` — детектор объектов для клика

- **Вход**: изображение капчи. **Выход**: bbox + класс.
- **Данные**: 25 000 изображений, ~150 000 инстансов. Классы — словарь промптов, которые
  реально приходят: `bus`, `car`, `crosswalk`, `traffic light`, `bicycle`, `stairs`,
  `chimney`, `animal`, … 30–60 классов на старте, расширять по логам.
- **Обучение**: YOLOv8s или YOLO11s, 640×640, 100–150 эпох, стандартные аугментации ultralytics.
- **Приёмка**: mAP50 ≥ 0.85 на своём val, recall@1 (правильный объект первым) ≥ 0.90 на
  golden-наборе 300 живых кейсов.
- **Закрывает типы**: `click`, `coordinates`, `hunt`, `basilisk`, `atbcaptcha`,
  `mtcaptcha`, `yidun`, `tencent`, `captchafox`. Один детектор — девять типов, поэтому он
  первый после поворота.

### 3.3 `bbox-v1`, `drag-v1`, `draw-v1`

- **Данные**: 8 000 / 10 000 / 8 000 изображений соответственно.
- `drag-v1`: классы источника и цели раздельно (`src_*`, `dst_*` или отдельный словарь).
- `draw-v1`: контур объекта — детектор + построение траектории обводки на стороне солвера.
- **Приёмка**: mAP50 ≥ 0.85, IoU предсказанного bbox ≥ 0.7 для `bbox-v1`.
- Покрывают по одному типу: `bounding_box`, `drag_drop`, `draw_around`.

### 3.4 Головы классификации: `hcaptcha-v1`, `recaptcha-v1`, `funcap-v1`, `awswaf-v1`, `shein-v1`

Каждая — отдельная голова на общем замороженном backbone.

- **Вход**: один тайл 224×224 (нарезка сетки делает сервис). **Выход**: вероятность «в тайле
  есть объект X» для каждого X из словаря.
- **Данные**: на голову — 100–200 промптов × 300–500 размеченных тайлов = **50 000–100 000
  тайлов**, из них 20% на валидацию. Бинарная разметка «есть/нет» по каждому промпту.
  Сетка: `3×3` кроме `funcap-v1` (`2×3`).
- **Обучение**: прогнать backbone один раз по всем тайлам → кэш фич `[N,768]` → логистическая
  регрессия по каждому классу (one-vs-rest). Никакой LoRA, никакого файнтюна backbone —
  контракт читает только `classifier.weight`.
- **Приёмка**: per-class AP ≥ 0.90, точность выбора тайлов на golden-наборе 200 кейсов ≥ 90%.
- **Закрывает**: `hcaptcha`/`hcaptcha_enterprise`/`classification_grid`,
  `recaptcha_v2`/`classification_grid`, `funcaptcha*`, `awswaf`, `shein`.

## 4. Данные: где брать и как размечать

1. **Харвест через свой же сервис.** Поднять шлюз, прогнать типы, где payload содержит
   картинку, и складывать входящие в S3. Это честнее публичных датасетов: снимаешь ровно
   то распределение, на котором будешь работать.
2. **Публичные наборы** как стартовый буст: датасеты hCaptcha/reCAPTCHA-сеток на HuggingFace,
   COCO-подобные для детекции объектов. Проверять глазами: у публичных капч-датасетов
   разметка часто сдвинута на тайл.
3. **Синтетика** — только для поворота и для балансировки классов в детекторах (композитинг
   объектов на фон).
4. **Разметка**: CVAT или Label Studio. Экспорт: детекторы — COCO JSON; головы — JSONL
   `{"tile": "path.jpg", "prompt": "bus", "label": 1}`; поворот — CSV `path,angle`.
5. **Golden-набор**: 200–300 живых кейсов на тип, замороженных, не участвующих в обучении.
   Это единственная метрика, которая коррелирует с продакшеном.

## 5. Приёмка артефакта

1. `make publish-model NAME=<name> VERSION=<v> PATH=<file> LABELS=<json>`
2. `make check-model NAME=<name> VERSION=<v> LOAD=1` — sha сошёлся, загрузчик поднял веса.
3. `make smoke KEY=<key> TYPE=<type>` — задача прошла через шлюз, в логах `solver.ready`
   и `task.done` без `ERROR_MODEL_INFERENCE`.
4. Прогон golden-набора: success rate не ниже порога из таблицы артефактов.

Модель без golden-прогона в прод не идёт: «на валидации 0.95» и «на живом трафике 0.4» —
обычная история.

## 6. Порядок

| шаг | артефакт | почему так |
|---|---|---|
| 1 | `rotate-v1` | синтетика, разметки нет, проверяет весь путь registry → солвер |
| 2 | `click-v1` | один детектор закрывает девять типов |
| 3 | `hcaptcha-v1` | самый частый трафик среди сеток |
| 4 | `recaptcha-v1` | то же, второй по частоте |
| 5 | `funcap-v1`, `awswaf-v1`, `shein-v1` | добивают сетки |
| 6 | `bbox-v1`, `drag-v1`, `draw-v1` | по одному типу каждый, низкий приоритет |

## 7. Деградация и ретрейн

- Пересчёт метрик на golden раз в месяц. Падение per-class AP на 10% — сигнал на ретрейн.
- Новый промпт в трафике, которого нет в `labels`, даёт `ModelInferenceError` с именем
  головы: это нормальный сигнал расширять словарь, а не баг.
- Версии в реестре неизменяемы: новый прогон = новая версия + `publish-model`, откат —
  `set_latest` на предыдущую.

## 8. Что считается сделанным

- [ ] десять артефактов в бакете, `make models` их показывает;
- [ ] `make check-model ... LOAD=1` зелёный для каждого;
- [ ] golden-набор заморожен и прогнан, success rate записан;
- [ ] `make smoke` по каждому семейству проходит без `ERROR_MODEL_INFERENCE`.
